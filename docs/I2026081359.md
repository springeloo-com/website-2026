Cause: Login can succeed with a read-capable session, but save (editorial workflow → branch + PR) needs write access. Resource not accessible by integration almost always means the OAuth App is not approved for the springeloo-com org, or the user lacks write, or the token is missing repo scope.

Fix (in order)
Write access
Repo → Settings → Collaborators → your user = Write (or org owner).

Approve OAuth App for the org (most common)
Org owner:
https://github.com/organizations/springeloo-com/settings/oauth_application_policy
Grant Springeloo Decap CMS access to the org / this repo.

Re-login with full scopes

Worker /auth must use scope=repo,user (see docs/howto-claudflare.md)
GitHub → Settings → Applications → Authorized OAuth Apps → Revoke Springeloo Decap CMS
Open /admin/ → log in again and accept the permission prompt
Verify
Save again. In DevTools → Network, a failing api.github.com call should no longer be 403.

Details are in docs/howto-decap.md under that error. No Decap field-config change will fix this — it’s GitHub org/token permissions.
