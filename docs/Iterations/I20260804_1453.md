This is definitive — not a Worker proxy bug.

| What you see | What it means |
|---|---|
| `token ghu_…` | GitHub **App** user-to-server token |
| empty `x-oauth-scopes` | Not classic OAuth |
| `contents=read` | App can list trees; **cannot** write |
| same `Iv23lijET9HfoEpCyj5H` | Worker secrets are from that **GitHub App** |

The proxy is working; it is minting the wrong **kind** of token. Decap needs a classic OAuth App → `gho_` with `repo`. `Iv23…` IDs exist for both app types — the prefix decides.

**Fix**

1. GitHub → **Settings → Developer settings → OAuth Apps** (not GitHub Apps) → **New OAuth App**
   - Callback: `https://springeloo-decap-oauth.mf-7e0.workers.dev/callback`
2. Put the **new** Client ID/Secret into the Worker (`GITHUB_OAUTH_ID` / `GITHUB_OAUTH_SECRET`)
3. Revoke the old app auth (and revoke the `ghu_` token you pasted here — treat it as leaked)
4. Log into `/admin/` again

You should then see `Authorization: token gho_…` and non-empty `x-oauth-scopes` including `repo`. Verify with:

```bash
export GH_TOKEN='gho_...'
bash scripts/check-oauth-chain.sh
```
