## Known save error (org permissions)

**Symptom:** Login works, but save fails with  
`Beitrag speichern fehlgeschlagen: API_ERROR: Resource not accessible by integration`

**Cause:** The OAuth session can read content, but save (branch + PR) needs
**write** access. This error almost always means:

- the OAuth App is not approved for the `springeloo-com` organization, or
- the user is not a **Write** collaborator on the repo, or
- the token is missing the `repo` scope (stale login)

### Fix (in order)

1. **Write access**  
   Repo → Settings → Collaborators → grant the editor **Write** (or org owner).

2. **Approve the OAuth App for the org** (most common)  
   Org owner:  
   https://github.com/organizations/springeloo-com/settings/oauth_application_policy  
   Grant **Springeloo Decap CMS** access to the org / this repository.

3. **Re-login with full scopes**  
   - Worker `/auth` must request `scope=repo,user` (see `docs/howto-claudflare.md`)
   - GitHub → Settings → Applications → Authorized OAuth Apps → revoke
     **Springeloo Decap CMS**
   - Open `/admin/` → log in again and accept the permission prompt

4. **Verify**  
   Save again. In DevTools → Network, `api.github.com` should not return **403**.

### How to prove the token can write

Client ID/Secret only mint tokens. Check the **user token** Decap uses:

→ **[howto-check-oauth-write.md](howto-check-oauth-write.md)**  
→ or: `export GH_TOKEN='gho_…'` then `bash scripts/check-oauth-write.sh`

Must show `x-oauth-scopes: … repo …`, `"push": true`, and create-ref **HTTP 201**.

Full details: `docs/howto-decap.md` (section on this error).  
This is not a Decap field-config bug — it is GitHub org/token permissions.
