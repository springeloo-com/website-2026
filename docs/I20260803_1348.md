Empty login after GitHub usually means the **OAuth popup never finishes the Decap handshake** (token not posted back), not a broken `/admin` route.

### What’s wrong
Your current Worker (old howto) likely:
1. Exchanges the code **without** the same `redirect_uri`
2. Uses a weaker `postMessage` pattern than Decap expects  

→ popup may “succeed” on GitHub, then admin stays on an empty login screen.

### What you must do (Cloudflare — not only Git push)

1. Open Worker `springeloo-decap-oauth` → **Edit code**
2. Paste the **new Worker script** from [`docs/howto-claudflare.md`](docs/howto-claudflare.md)
3. Confirm secrets `GITHUB_OAUTH_ID` / `GITHUB_OAUTH_SECRET`
4. **Save and Deploy**
5. GitHub OAuth App callback must be exactly:  
   `https://springeloo-decap-oauth.mf-7e0.workers.dev/callback`

Site config is already updated (`auth_endpoint: auth`, `site_domain`) in commit `170351c`.

### How to test the forward after success

| Step | What to check |
|------|----------------|
| 1 | `…workers.dev/` → “Hello! Decap OAuth Proxy…” |
| 2 | `…/auth?provider=github` → redirects to GitHub |
| 3 | Open `/admin/`, allow popups, click login |
| 4 | **Inspect the popup**: after GitHub, URL has `/callback?code=…`, page says **Authorizing Decap…** |
| 5 | If popup shows `OAuth token error: …` → secrets/callback mismatch |
| 6 | Success = popup closes and you see **Site content** collections |

Full checklist: [`docs/howto-claudflare.md`](docs/howto-claudflare.md) §5.

**Critical:** Redeploy the Worker with the new script first — the site deploy alone won’t fix the empty post-login screen.
